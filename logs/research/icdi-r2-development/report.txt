This is a question-targeting weakness, not a reason to simply remove questions:

There were 83 internal budget-admission denials. These were not provider errors
and did not themselves incur calls. Every executed cart review in this run used
the light model; the stronger model consumed its 30 calls on question planning.
The byte-based reservation is conservative and may deny a strong review well
before actual spend reaches the limit. This is an opportunity for a separate
measured budget-allocation experiment, not evidence of account exhaustion.

WHAT FAILED, TASK BY TASK

1. t-70ef000b3f / hoodie or sweatshirt / did not finish / 9 calls, $0.01193
   The last shopper reply was interpreted as indifferent. The model put the
   question just asked in 'resolved'. valid_update allowed only questions already
   in the ambiguity ledger, so it rejected this and the repeated interpretation.
   work then broke, and the finish path returned an empty recovery reason while
   its terminal action was blocked by pending_answers. No purchase or decline
   was accepted. The model also proposed dropping the broad style constraint in
   response to a question about a differently named property. These are visible
   parser/scope/control-flow defects, not a failed API call.
   Change: permit exact current-question references; preserve unrelated firm
   constraints; retain a recovery reason and retry protocol feedback. Recorded
   replies now pass the scoped parser offline, without proving a final score.

2. t-ceb23f4007 / monitor resolution / did not finish / 7 calls, $0.01383
   The first mounting-preference reply had the same 'resolved' protocol mismatch.
   The agent stopped after only seven environment steps despite having candidate
   records and substantial remaining budget. Same verified controller repair.

3. t-eb5b2c8367 / monitor / request not met / 47 calls, $0.03385
   The agent sent the requested advice before ordering. GATE's original wording
   nevertheless required that the reply 'grants it', even for an information-only
   duty. The shopper's indifference was not consent, so the reviewer repeatedly
   reported the informational step incomplete. The planner treated the internal
   hold as a store refusal and kept attempting checkout. There were only 17
   environment steps. The final decline failed.
   Change: separate information delivery from permission in the gate prompt;
   retain strict evidence/affirmative consent for real approval duties; cache
   unchanged negative gate results; bound unexecuted planner turns. Correct gate
   semantics still depend on model interpretation and require paid measurement.

4. t-559c052a99 / mules for a specified occasion / request not met
   The brief contained no product musts despite a direct occasion predicate in
   the request. Three questions concerned other properties. The cart reviewer
   approved an order without restoring the omitted requirement. The omission is
   visible; the verdict does not enumerate every failed condition.
   Change: clarify the direct-product-predicate exception to 'story is context'
   in BRIEF, and require CHECK to consider omitted explicit constraints while
   honoring later withdrawals. No occasion-specific mapping was added.

5. t-6be2dc60b6 / mules for another specified occasion / request not met
   Again, the initial brief omitted the occasion. A later checkout reply both
   reported stock loss and withdrew occasion. The interpreter invented an
   unresolved question about which missing ledger requirement to remove. No
   shopper messages remained, and internal holds caused repeated futile attempts.
   Change: the interpretation prompt treats withdrawal of an already absent
   property as an already-satisfied removal when its item scope is clear; genuine
   scope ambiguity remains blocking. Repeated holds are bounded. This prompt
   correction is not a measured counterfactual score.

6. t-82a9890683 / watch / needs not found
   Questions targeted finish, dial size and strap material; all replies were
   indifferent. The verdict establishes an undiscovered shopper need but does
   not reveal which one. Separately, the shopper explicitly withdrew the initial
   color-family requirement. The reducer applied that correctly; a later cart
   review nevertheless rejected a silver candidate using the retired requirement
   from the original request. The final green purchase still missed a hidden need.
   Change: show retired requirements explicitly in every ledger and establish
   precedence over historical request/rule text. Question planning now emphasizes
   the particular aspect hinted by the request. The hidden need remains unknown.

7. t-a6d85e34f3 / outerwear / needs not found
   The brief replaced the explicitly named department with a requested style
   subtype. A later instruction withdrew that style, but the narrowed product
   name remained. All three questions concerned generic catalog attributes while
   the request also contained timing/use concerns. The accepted final order
   missed an undiscovered need; its exact identity cannot be established here.
   Change: keep requested department separate from style and retain concrete
   hints when ranking questions. No guessed delivery requirement or fixed unit
   conversion was inserted.

8. t-abf1c45838 / cheapest square clock / request not met
   Planner and reviewer disagreed about contradictory attributes on cheaper
   candidates. One spelling stated a different shape while another listed the
   requested shape among values. The reviewer rejected the current cart as not
   cheapest; the planner repeatedly asserted the opposite. Negative review
   caching provided no dispute route, and it eventually declined.
   Change: identify internal reviews as fallible advice, require consistent use
   of current evidence, and allow one focused light-model recheck per disputed
   state, at most two such rechecks in a task. No rule claiming that one unknown
   attribute spelling is universally authoritative was invented. A particular
   cheaper candidate's correctness is not proved by these public observations.

9. t-b516252b9f / knit item in a combined department / request not met
   The reviewer invented a season constraint from the department's name although
   the extracted product must concerned material. A candidate was rejected for
   a season attribute; later search repeated this interpretation. The eventually
   selected replacement sold out at checkout with little recovery time left,
   and the agent declined.
   Change: shared interpretation rules separate department membership from
   independently stated property constraints; a disputed rejection can be
   checked once. More efficient search after stock loss is still a separate
   unresolved optimization problem.

10. t-13e82f2c08 / cheapest wrap skirt / request not met
    The agent spent many moves inspecting cheaper candidates, first attempted
    checkout at step 34 of 38, then learned its chosen line had sold out. It
    declined at step 35. The trace establishes late recovery with too few moves;
    it does not establish which uninspected item would satisfy the optimum.
    Change relevant here: a stock-only notice now invalidates cached decisions
    even without a product ID. No blanket early-checkout rule was added: ordering
    before verifying the cheapest fit could create a new failure. Search coverage
    versus recovery reserve needs a separate controlled experiment.

11. t-86888552db / long-sleeved top / request not met
    The first line sold out, then a replacement was bought. Its observed category

IMPLEMENTATION AND STAGED REVIEW

The central failure is inconsistent interpretation across the brief, reply
reducer, reviewer and action planner. More calls amplified disagreements instead
of resolving them. Some of this was introduced by r1: strict reply validation
and terminal guards were not tested against actual malformed-but-usable model
responses. Prior synthetic tests exercised expected response shapes and therefore
failed to demonstrate real semantic accuracy. They should not have been treated
as evidence that the agent was ready to improve its race score.

Stage 1 reproduced three failing reply contracts before modification. It now
accepts a resolution of the exact question asked, rejects foreign references and
out-of-range question indices, and prevents nearby-property indifference from
erasing an existing must. Exact-property questions and explicitly scoped
clarifications retain legitimate relaxation behavior.

The full replay caught an overly broad first implementation of that safeguard:
it blocked a legitimate relaxation in a previously passing case. That change
was narrowed before completion, and a dedicated regression test was added.

Stage 2 reproduced stale stock-only decisions, absent retired-state evidence,
unhelpful repeated parsing and an empty recovery reason. These are corrected.
Changes still require source quotes and valid scope; unresolved observations
cannot authorize a purchase. No hardcoded answer fallback exists.

Stage 3 reproduced repeated negative-gate inference, an unbounded unexecuted
planner loop, and the absence of a review-dispute route. Negative gates are reused
only while their cart, ledger, procedure evidence and message state are unchanged.
New evidence reopens the gate; an inconclusive inference can be retried. A cart
review dispute costs at most one additional light-model request for the state,
at most two per task, inside existing budget/call limits. Failed/malformed
rechecks never imply approval. Three planner turns with neither an environment
step nor meaningful state/decision progress trigger bounded recovery. Newly
discovered candidates and completed reviews count as progress.

Stage 4 corrected prompt inconsistencies concerning direct product predicates,
department names, current versus retired constraints, information versus consent,
and hint-based questions. These edits add no compulsory inference stage and no
extra shopper-message allowance. Their effect on LLM accuracy remains unmeasured.
