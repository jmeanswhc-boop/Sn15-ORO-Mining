1. Evidence and implementation boundary

The supplied ten-case run was local-48ea2d82b735402084cd09cc2fcc2f39, using the unchanged Tosky_v2 source. Its recorded replay reproduced all 564 requests exactly. All ten episodes stopped without dispatching checkout or decline. The recorded model requests succeeded; an OpenRouter outage did not explain these ten failures.

All 20 additional source audits returned complete:false. All 42 cart proofs were rejected before the later property/objective matcher was reached. The first rejection was the global completeness gate for 29 responses and assignment validation for 13: six prose-evidence shapes, three stringified JSON-value shapes, three required-view failures and one reported product-type failure. Both the extra gate and the representation contract contributed to the unfinished episodes.

The recovery candidate therefore starts from full v4. It does not carry over the broad Tosky_v2 source/proof controller. The original 362 v4 method ASTs are identical in the candidate. New reachable behavior is confined to ReviewBoundaryControls, placed first in Episode's inheritance order. Its hooks are initialization, disputed-review adjudication, dependent review context and accounting for the new inference role.

The ordinary cart checker, product-coverage audit, interview, reference resolution, search, cart procedures, terminal safeguards and transport implementation retain their original v4 methods. This is a recovery candidate with a controlled scope; it is not an attempt to combine a new shopping architecture with this correction.

2. Stage one: runtime requirement and observation references

Each corrective review gets a revision and identifiers generated from the active runtime requirements and observed facts. A fact retains the actual product, field scope, key and JSON value in code-owned state. The model selects those identifiers; it does not reproduce requirement text as a key or copy prices, booleans and field values into a second representation.

Every active requirement must appear exactly once for a matching candidate. Unknown, extra, duplicate, cross-product and stale references are rejected as format faults. Indifference and withdrawn constraints do not create requirement identifiers. Budget, quantity and availability constraints remain separate typed checks. Message and step ceilings do not become owed actions.

Initial snapshot checks passed before response parsing was connected. The final suite also checks boolean/numeric preservation, known-empty fields, omitted fields, changing requirements and genuine observation changes.

3. Stage two: distinguish formatting from shopping decisions

The decoder produces FORMAT_ERROR, MISSING_EVIDENCE, MISMATCH, BETTER_OPTION or APPROVED. Transport/admission failures produce UNAVAILABLE. Format diagnostics name the exact bad field path.

A format error changes neither the basket nor the original negative verdict/message. It gets a format-only correction opportunity using the same observed snapshot. Supported semantic decisions are retained; a format-only retry cannot upgrade a prior unknown, mismatch or different-component claim into a positive match. If the representation cannot be repaired within the transmission allowance, the original review remains unresolved.

A supported semantic problem is handed to the existing shopping planner with the relevant requirement or candidate. Approval lifts an existing negative review only after full identifier coverage, same-candidate evidence, the model's same-property/entity judgment and code-owned global constraints pass. The code validates grounding and consistency; the model still judges semantic entailment. An evidence ID alone is not an independent semantic verifier.

All 42 raw recorded proof responses were exercised against the new decoder. The six prose-evidence failures and at least three stringified-value failures also exercise the bounded format-only handoff with controlled corrective replies and world calls prohibited. This is a protocol regression test, not rescoring those products as correct.

4. Stage three: observation, objectives and cached text

The ordinary review consumes facts that were actually observed. It does not reinterpret the shared reference helper's fresh-offer predicate as a universal requirement to repeat an already completed datasheet read. All three recorded detail/offer failures are covered. The original shared page predicate and explicit procedure enforcement remain unchanged.

For pick=any, unrelated alternatives are excluded from this corrective decision. For cheapest, a potentially cheaper candidate must satisfy the requested product type and every active need before it can count as eligible. A wrong subtype is excluded. Unknown availability cannot establish a better in-stock alternative. More expensive records do not create a new completeness obligation.

Long cached text can supply exact, explicitly partial excerpts near words from current runtime needs. The full original field stays in code-owned state; the transmitted preview is marked partial. Literal token matching only selects display excerpts and never determines product eligibility. Empty fields are reported as observed empty, and genuinely omitted content is not treated as inspected evidence. No fixed product-property, synonym or unit registry was added.

This addresses the earlier seven independent counterexamples at the recovery boundary: typed stock evidence, semantic property naming, ordinary value spelling, unavailable-review caching, clipped-value representation, cheaper wrong-type alternatives and the original affordable-empty decline path. Semantic binding and spelling checks use controlled model judgments and do not establish live model accuracy.

5. Stage four: cache and checkout handoff

The cache signature includes the current active requirements, quantities, budget/scope, bindings and relevant product observations. A step-counter increment or unchanged repeated read is not a new corrective state. The existing shared limit of two dispute decisions per episode is retained.

An approved correction stores its context after promotion to a positive verdict. The context also tracks relevant cheapest alternatives, including newly observed cheaper records. Changing a relevant price, stock state, product field or requirement invalidates it. Unrelated updates do not invalidate an any-objective correction. A snapshot that changes while inference is outstanding cannot be promoted.

Full-flow verification exposed a preservation issue: v4 can review a small search before assigning price/stock field names. Requiring those bindings in every correction would create a new missing-price hold. The new typed path therefore defers to the original v4 adjudicator when those bindings are absent. It also defers for multi-item carts, active reference requirements, empty requirement ledgers, unsupported objectives or overly complex candidate sets. The typed scope is one item/line, any or cheapest, at most six alternatives and twelve candidate/requirement cells.

Five controlled full entrypoint flows pass through the real ProxyClient with HTTP replaced locally: healthy purchase, disputed-review purchase, malformed-review correction followed by purchase, rejected checkout with a changed-budget notice, and decline when all observed options exceed the budget. The healthy flow sends identical model requests and world actions in unchanged v4 and the candidate. The original procedure tests retain checks for performed actions and actual evidence; review approval does not complete a workflow duty.

6. Stage five: bounded cost

AGENT_USD_LIMIT remains 0.035. PROCEDURE_USD_RESERVE remains 0.010 within that allowance. CALL_CAP remains 60. Models and pricing configuration are unchanged. The new correction uses the existing dispute order, SPARE then LIGHT, and at most 768 output tokens per physical request.

One new corrective decision permits at most two physical transmissions in total. Initial inference, format correction and parameter-compatibility retry share those two slots. Every transmission passes through the existing reservation/settlement ledger. Missing cost and uncertain transport retain conservative reservations. HTTP 402 remains a global stop. New reasoning-parameter compatibility state is isolated from the existing roles. Corrective inference cannot borrow procedure-only funds, even if invoked from a procedure budget context.

The first packet draft did not fit two conservative reservations in the recorded monitor state. The transmitted packet was reduced to current requirements, candidates and fact references, removing repeated full request narrative and repeated field identities. This also removes a source of invented obligations. A packet over 12,000 UTF-8 bytes returns unavailable without transmission.
