Both new versions are implemented: agents/ICDI_chidori_v3.py and agents/ICDI_chidori_v3_budget.py. Earlier agents and the archived champion remain unchanged. No paid model requests, practice evaluations, qualifying submissions or races were run. The work establishes specific control-flow corrections and offline regression evidence; it does not establish a new score or champion-level performance.

The principal engineering failure was interpreting a request that did not fit the local allowance as globally unavailable credit. The latest supplied v2 run scored 16/30, with 19 tasks entering local inference shutdown. All 14 failures occurred in that group. Its 405 agent inference HTTP requests returned 200; there was no recorded 402. Spending on each task was below 60% of the configured $0.035 allocation. The 19 shutdown states all had sufficient allowance for a compact notice-reading request. This is evidence of a local control defect, rather than a demonstrated exhausted OpenRouter account in this particular verification.

The consequence extended beyond stopping an optional expensive request. A denied heavy review could disable a cheaper correction. Failed notice reads were recorded as heard. The fallback could then order an unchanged cart despite a valid negative review or a stockout. Eight failed tasks followed an unavailable-listing checkout with unsuccessful recovery. These observations explain a common failure chain; they do not prove that fixing it will recover all fourteen lost tasks.

My previous verification had several weaknesses, with concrete countermeasures in this update:

- Replacing the entire proxy client with a fake concealed the earlier unauthenticated catalog-GET failure. Both v3 files now undergo tests through the actual ProxyClient and mocked HTTP. All real requests are blocked. The old 401 behavior is reproduced as a negative control, and both new agents use authenticated inference POSTs without a catalog GET.
- Tests accepted a broad shutdown instead of checking whether cheaper work remained feasible. The new tests reproduce expensive-request refusal followed by affordable recovery, and replay all nineteen recorded stopped states. Genuine 402, exhausted allocation, invalid pricing and accounting-envelope breach still stop inference.
- Completion flags were advanced before a usable interpretation. Notices now remain pending until a valid interpretation is applied. Missing or malformed cart reviews cannot become cached approvals. A malformed escalation cannot overwrite a valid prior review.
- Pricing used every model's highest context tier on ordinary short prompts. Admission now selects the maximum applicable published tier under the existing conservative byte/framing estimate, retaining the 25% margin and maximum-tier fallback. It does not replace the estimate with an average characters-per-token assumption.
- Synthetic passing tests were given too much weight as evidence of real proficiency. The final evidence distinguishes unit tests, frozen-price trace replay, admission changes and actual accuracy. No new accuracy figure is claimed.

Checkpoint A passed before recovery changes were added. Its initial six tests cover request-specific denial, actual exhaustion, a 402 without retries, invalid pricing, immediate loop exit after local refusal, and the nineteen recorded stopped states. Ordinary refusal sets request_denied and leaves remaining priced funds usable; it does not set no_credit. This also avoids treating local refusal as a server outage and entering the outage sleep loop.

Checkpoint B passed eighteen tests before tier changes were added. Both agents now retain pending notices, bound repeated interpretation attempts at an unchanged public state, and apply a successful notice once. Withdrawn and replacement requirements update the existing ledger. Checkout is held for unprocessed notices, unavailable current lines or a valid negative current-cart review. The normal planner receives the repair reason. Forced finish returns the reason instead of buying the known invalid cart or immediately declining after a blocked purchase. The budget variant also honors a negative existing procedure gate during forced finish.

Review results require an actual boolean ok field. A valid light review survives an unavailable or malformed heavy escalation. Unknown results remain uncached and eligible for retry. Review caching includes the current requirements, quantities and public listing records, allowing fresh evidence to trigger reconsideration. This does not add an always-on reviewer or replace search, interviewing, compatibility or product-selection algorithms. The full agent retains its existing procedure controller; the budget variant retains its original procedure strategy and prompts.

Checkpoint C passed twenty-four tests before final integration. It checks exact tier boundaries, malformed tier data, conservative fallback, nonmonotone applicable tiers, unchanged reply capacity when affordable, and all 405 recorded bills and token counts. Haiku's threshold is 100,000 estimated prompt tokens; Luna's is 272,000. Sonnet's configured rates are unchanged. These settings were cross-checked against public OpenRouter metadata on 2026-11-12:

At identical recorded request bodies, median admission reservations fall by about 5x for Haiku and 1.78x for Luna. Sonnet reservations are unchanged. These are reductions in estimates used to admit requests, not measured reductions in money charged. The estimates remain conservative: median new reservation/reported-cost ratios are approximately 10.95 for Haiku, 43.55 for Luna and 2.64 for Sonnet. Further reducing those ratios would require a justified tokenizer/route bound or a separately tested inference policy; this version does not introduce either.

Final regression testing passed 309 tests, including 129 targeted v3 checks. Both variants are covered by physical-attempt accounting, timeout/rate-limit reservation, malformed/missing usage, 402 handling, the actual proxy transport, ninety-task accounting workloads, previous-source hashes and local source-policy checks. An additional real-client scenario executes rejected checkout, interpreted stockout and withdrawn requirement, cart replacement, valid review and successful checkout. Its HTTP boundary is mocked. Another confirms that a denied heavy escalation preserves a negative light review and consumes only the one admitted inference attempt.

Recorded passing controls exposed an error in my initial stricter validation: two valid notice responses supplied the public item name instead of its number. That would have rejected working behavior. The parser now resolves numeric references or a unique exact normalized public item name, while rejecting ambiguous or out-of-range references. Dedicated tests cover this correction. No benchmark-specific names were added to either agent.

Eleven of the sixteen previously passing tasks had uninterrupted recorded inference histories. Replaying v2 first reproduced all eleven end to end, validating the replay harness. With pricing fixed at v2's settings to isolate the recovery changes, both v3 variants reproduce all eleven public action/request sequences. Budget-variant replay adapts only its deliberately different briefing-schema prefix, using zero-duty recorded briefs. The other five passing tasks had stopped inference and finished through fallback; there is no recorded response for the additional requests v3 can now make, so they cannot be completed as faithful counterfactual replays.

With complete v3 pricing enabled, all eleven controls reach the first newly affordable Haiku director request where v2 previously fell back to Luna. Replay stops there, before supplying a different model's recorded answer. This is an intentional admission change, not eleven measured failures and not eleven demonstrated successes. Consequently, frozen-price replay supports preservation of recovery flow; it cannot certify full-v3 accuracy, latency or total request count. The relevant output decisions are unobserved without new evaluation.

The ninety-problem financial envelope remains explicit. Both agents retain a $0.035 per-problem agent allocation: $3.15 across ninety tasks, leaving $1.85 below the user's $5 total cap. To meet a $4 operating target with $1 final headroom, simulator charges and all other costs would have to fit within $0.85. These amounts are allocations, not expected actual spending. Missing usage and uncertain transport retain their reservations, every physical attempt is admitted separately, and true remote credit exhaustion cannot be reopened by protected work.

The supplied agent logs do not establish all simulator/shared-key charges, and published rates plus a conservative input estimate are not certified future routed-price bounds. A fixed per-task ledger also cannot transfer unused funds between isolated task processes. Therefore neither these tests nor the $3.15 arithmetic certify the full shared ninety-task bill. No cap was increased or bypassed to obtain the offline results.

Local AST/source preflight passes for both files: one synchronous agent_main, source below one megabyte, approved imports/proxy routes, no new direct network or filesystem access, and no concrete task/product IDs or grader logic. Nine existing methods changed and four controller methods were added per variant; prompts and other methods are preserved against the corresponding v2. Private server integrity/novelty checks were not run and cannot be certified locally.

The next evidence required before claiming improved proficiency is a paired scored comparison using matching public tasks, recording individual gains/losses, cost per correct task, all shared billing, request counts and latency tails. It must test the newly reachable model decisions rather than reuse old answers. That evaluation has not been authorized or performed here. Both new files are engineering candidates for review, not demonstrated replacements for a champion.
