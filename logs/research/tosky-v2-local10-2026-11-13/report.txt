DEFINITIVE FINDING

This run provides the internal evidence that was unavailable in the public qualifying incident. The exact tested source hash is 526f7badf9dd20dd671ee4b089bb5a9c400af305bccae6980c87048128872173, matching agents/Tosky_v2.py. All ten executions scored zero and stopped without sending an order or decline. All 322 inference requests succeeded. There were no agent crashes. Only two cases encountered local request-admission denials, so those denials do not explain the common failure in the other eight.

The central defect is an inconsistent review boundary and incorrect error routing. A model can say that the chosen product meets the request, but return evidence in the wrong data shape. The program then rejects that representation, stores a negative cart verdict, and sends the model's shopping commentary to the shopping planner as though the product had failed. It never tells the planner the actual failing JSON field. The planner searches, swaps products or rereads pages rather than repairing the review representation. Other reviews refuse to certify an unnecessarily broad notion of completeness, including global limits, unrequested objectives and irrelevant unknown alternatives. The combination prevents completion.

The correction must distinguish three separate questions: whether the response follows the protocol, whether the selected product meets the active requirements, and whether the agent has performed a required action. A formatting error is not evidence of a bad product. A warning about unrelated catalog information is not an unmet request. A fully opened attribute page and a fresh price offer are separate observations.

SOURCE AUDIT FAILURE IS A CONTRACT PROBLEM

All twenty responses are valid JSON and explicitly complete=false. Examples turn the ceilings of three messages and thirty-eight moves into owed workflow actions, such as messages=3 or actions=38. Budget and stock obligations are also proposed as textual product attributes even though the existing brief already carries them separately. The audit combines product normalization, global ceilings, workflow duties and conversational context into one certificate, then discards the entire response when it cannot certify all of them.

The skirt case shows the cost of that coupling: its real style requirement is not in the active ledger, but a useful proposed style normalization is never installed. Simply forcing complete=true would still be unsafe: the response's previous field invents constraint text rather than identifying an actual existing ledger entry, and some proposed duties confuse maxima with required work. The existing v4 product-coverage mechanism should be preserved during recovery; the broader v2 audit should not be ported wholesale.

FINAL REVIEW FAILURE IS MORE THAN A CAUTIOUS MODEL

The bomber and watch examples contain affirmative product judgments that the program rejects for representation errors. The exact invalid field is not returned to the repairer. cart_check instead uses answer.problems as its error message, even when those strings merely note that the style is correct, that alternatives fail, or that unrelated text may be clipped. That feedback cannot tell the next model to change assignments[0].evidence from a string to an array.

The producer and consumer also disagree about requirement identity. The program requires exact copying of a live need string, while responses rewrite it, add stock/budget rows or list indifferent topics as missing. A response saying "sleeveless" does not match a live key "sleeves: none". After fixing evidence typing, these other contract failures would become active. This is why a one-line coercion or deleting a completeness check is insufficient.

For pick=any, the new packet unnecessarily supplies alternative candidates and asks for broad objective verification. In the milk and wedge cases, the reviewer demands proof about cheaper or unread alternatives even though any eligible selected item is acceptable. It also treats an unconditional listing_text_may_be_clipped=true as evidence that every record is incomplete. That flag is set even for small fully visible records and known empty descriptions. Indifference is recorded in the original replies but is not supplied as an authoritative typed state, allowing aesthetic hints to become hard requirements again.

The monitor response contains the distinct content error that 4 ms fails an "at least 1 ms" requirement. It has not yet reached numeric validation in this run, so it must be retained as a semantic negative-control fixture for subsequent work, rather than being counted as the current first rejection.
